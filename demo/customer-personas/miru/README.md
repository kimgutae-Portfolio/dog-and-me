# 가상 고객 페르소나: ミル

현재 WAN MEMORY 신청 폼과 `FILM MOOD`의 빈 샘플인 `はじめての春`, `はじめての海`를 함께 테스트하기 위한 말티즈 합성 데모 자료입니다. 고객, 반려견, 에피소드와 사진은 모두 가상이며 실제 고객 자료가 아닙니다.

## 페르소나 설정

- 보호자: 横浜市에 사는 30대 1인 가구 `鈴木 奈緒（架空）`
- 반려견: 보호 단체를 통해 2026년 1월 가족이 된 3살 추정 암컷 말티즈 `ミル`
- 성격: 낯선 것을 조심스럽게 살핀 뒤 보호자를 확인하는 차분하고 응석 많은 성격
- 이야기 축: 가족이 된 뒤 처음 맞은 봄 → 처음 만난 바다 → 집으로 돌아온 평범한 저녁
- 무드 테스트: 같은 신청 데이터를 `はじめての春` 중심안과 `はじめての海` 중심안으로 각각 해석

## 현재 폼 기준 테스트 방법

1. `form-submission.json`의 `form` 내용을 신청 폼에 입력합니다.
2. 기본 정보에서 이름, 읽는 법, 견종, 나이와 성격을 입력합니다.
3. 이야기 입력 단계에서 JSON 순서대로 **정확히 5개**를 입력합니다.
4. 각 이야기 카드에 사진을 **최소 1장씩** 연결합니다. 데모에서는 아래 사진을 사용합니다.
   - MEMORY 01: `04-first-spring-cherry-path.png`
   - MEMORY 02: `05-first-sea-wave.png`
   - MEMORY 03: `06-after-sea-nap.png`
   - MEMORY 04: `07-first-neighborhood-walk.png`
   - MEMORY 05: `08-window-morning.png`
5. `01-primary-face-home.png`, `02-primary-body-home.png`, `03-side-tail-neighborhood.png`는 캐릭터 확인용 보조 사진으로만 보관합니다. 고객 입력에서 별도 얼굴·전신·옆모습 슬롯을 요구하지 않습니다.
6. `その子へ伝えたいこと`를 입력합니다.
7. 확인 화면에서 4개의 필수 동의를 모두 체크한 뒤 테스트 주문을 제출합니다.

현재 폼에는 외형 시기, 스타일, 화면 비율, 내레이션, BGM, 인물 포함 여부를 고객이 선택하는 항목이 없습니다. 따라서 이 페르소나에도 해당하는 구형 입력값을 넣지 않았습니다. 스타일은 `実写に近い愛犬と、やわらかな絵画表現`, 화면은 `16:9 横型`, 내레이션은 없음, BGM은 디렉터 선택이라는 현재 고정값을 따릅니다.

## 사진 구성

- 사진 01: 얼굴 기준. 눈 간격, 코, 짧고 둥근 입 주변, 귀 끝의 옅은 아이보리색 확인
- 사진 02: 전신 기준. 작은 체형, 다리 길이, 중간보다 짧은 털, 파란 목줄 확인
- 사진 03: 옆모습·꼬리 기준. 몸통의 비율과 등 위로 높게 말린 꼬리 확인
- 사진 04: `はじめての春`. 벚꽃잎을 올려다보며 앞발을 든 장면
- 사진 05: `はじめての海`. 작은 파도가 앞발에 닿자 조심스럽게 내려다보는 장면
- 사진 06: 바다에서 돌아온 저녁. 수건 옆에서 잠든 일상 장면

## 운영 테스트 포인트

- 현재 폼이 요구하는 추억이 정확히 5개이며 각 설명이 30자 이상인지
- 기준사진과 추억사진이 서로 다른 업로드 자산으로 저장되는지
- 사진 5장이 MEMORY 01~05 역할에 정확히 연결되는지
- 구형 `dog_behavior`, `appearance_policy`, 고객 선택형 스타일/BGM 필드 없이 제출되는지
- 인물이 없는 사진에서도 고정 인물 정책 문구와 사진 권한 동의가 정상 저장되는지
- 동일 신청 데이터에서 `film_mood_tests`의 2개 구성안이 서로 다른 중심 장면을 가지면서도 같은 개체성과 결말을 유지하는지

이미지는 Codex의 기본 이미지 생성 기능으로 만든 데모 전용 합성 사진입니다. 실제 고객 사례나 포트폴리오로 오인될 수 있는 방식으로 공개하지 않습니다.
