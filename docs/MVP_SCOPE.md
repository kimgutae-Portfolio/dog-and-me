# 1次開発の範囲

## 目的

最初の開発では、AI動画生成の自動化より先に次の3点を検証します。

1. 日本のお客様にサービスの価値と安心感が伝わるか
2. 感情的な負担なく、愛犬の話と制作希望を入力できるか
3. 受注後の確認プロセスが見え、安心して待てるか

## 今回実装した範囲

| 領域 | 状態 | 内容 |
| --- | --- | --- |
| ブランドサイト | 完了 | 今を残すメモリーフィルム、作品トーン、制作フロー、料金、FAQ |
| 相談フォーム | 完了 | 3ステップ、物語3〜5項目、各物語の写真1〜3枚、自動保存 |
| 写真 | 完了 | private Storageへ直接送信。HEIC変換、制作中の追加送信 |
| 制作室 | 完了 | 顧客別注文、進行、映像構成案選択、場面イメージ承認、メッセージ、修正、納品 |
| レスポンシブ | 完了 | PC、タブレット、モバイル |
| 認証 | 完了 | Supabase Auth（メール・パスワード、確認メール、再設定） |
| DB・Storage | 完了 | 注文、素材、進行、映像構成案、納品のRLSとprivate bucket |
| 決済 | 完了 | Stripe Checkout、Webhook署名検証、入金・返金の自動反映 |
| 管理画面 | 完了 | 注文一覧、状態、入金、納期、2案公開、場面イメージ公開・調整、完成映像納品 |
| 動画制作 | 手動運用 | 外部の動画生成AIで制作し、制作時間・ツール使用量を記録して完成品を管理者がアップロード |
| AI自動生成 | 範囲外 | 品質検証後の第2段階 |

## 1次運用の成立条件

- 相談受付時点では課金せず、担当者が素材と納期を確認する
- 写真はprivate storageへ直接アップロードし、アプリサーバーを経由させない
- AI生成結果をお客様へ自動公開しない
- 1次運用では「いまを残す」映像だけを受け付け、ほかの制作目的は品質と運用手順が整ってから公開する
- WAN MEMORY独自のAIモデル学習、広告、ポートフォリオ公開に写真・動画を使わない。外部生成AI・映像制作サービスでの処理は各サービスの条件を案内し、注文単位の同意記録を残す

## 次のスプリント

1. Supabaseのメールテンプレートと本番SMTPを設定
2. Stripeテストモードで決済・キャンセル・Webhook・返金をE2E確認
3. Resendで進行通知を接続
4. 実注文10件を手動制作し、品質・時間・動画制作ツール使用量を計測
5. 計測後に通常価格とAI自動化範囲を確定

AI Provider連携とFFmpeg自動レンダリングは、この運用データを確認した後に進めます。
