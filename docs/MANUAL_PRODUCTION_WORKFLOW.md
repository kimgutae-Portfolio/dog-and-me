# WAN MEMORY 수동 제작 운영 흐름

## 목적

초기 운영에서는 GPT와 Runway를 API로 자동 연결하지 않는다. 고객 자료, GPT 분석 결과, 컨셉, Runway 프롬프트와 생성 결과를 주문 단위로 분리해 저장하고, 운영자가 앞 단계의 결과를 승인한 경우에만 다음 단계를 연다.

고객에게 보이는 `orders.status`는 큰 진행 상태만 표현하고, 운영자만 보는 세부 작업 상태는 별도 제작 작업판에서 관리한다. 이렇게 해야 고객 화면이 복잡해지지 않으면서도 잘못된 사진이나 미승인 결과가 다음 단계로 넘어가는 것을 막을 수 있다.

## 전체 순서

```text
0. 주문 접수·자동 점검
   ↓ 통과
1. 사진·신청 내용 분석
   ├─ 고객 보완 필요 → 고객에게 요청 → 1단계 재검토
   └─ 운영 승인
       ↓
2. 컨셉 A·B 작성 및 고객 공개
   ↓ 고객이 1안 선택
결제 요청·입금 확인
   ↓ paid
3. 선택 컨셉 제작 가이드 작성
   ↓ 가이드 확정
4. 외형 유지 테스트 1건 생성·검수
   ├─ 실패 → 프롬프트 수정 후 재생성
   └─ 승인
       ↓
5. 장면별 수동 생성·검수 (장면 스틸 이미지 우선 생성)
   ↓ 모든 필수 장면 사용 가능
5.5 장면 스틸 고객 공개 (`stills_review`)
   ├─ 고객 조정 요청 (최대 2회, 메시지로 접수) → 스틸 재생성·재공개
   └─ 고객 승인 → `production` 전환, 승인된 스틸만 영상화
   ↓
6. 약 1분 편집·내부 최종 검수
   ↓
7. 고객 확인 영상 공개
   ├─ 수정 요청 → 제작·편집 → 고객 재확인
   └─ 고객 최종 승인
       ↓
8. 최종 납품
```

## 상태를 두 층으로 관리하는 이유

### 고객에게 보이는 주문 상태

기존 상태를 유지한다.

| 주문 상태 | 고객에게 보이는 의미 |
| --- | --- |
| `materials_submitted` | 상담 접수 완료 |
| `reviewing_materials` | 사진과 이야기를 확인 중 |
| `concepts_ready` | 컨셉 2안 확인 가능 |
| `concept_selected` | 선택한 이야기의 제작 준비 중 |
| `stills_review` | 장면 이미지(스틸) 확인 요청 — 고객 승인 후 영상화 시작 |
| `production` | 영상 제작 중 |
| `customer_review` | 완성 전 영상 확인 요청 |
| `revision_requested` | 수정 반영 중 |
| `quality_check` | 고객 확정 후 최종 확인 중 |
| `delivered` | 납품 완료 |

### 운영자에게만 보이는 세부 단계

관리자 화면 상단에 다음 8단계 체크리스트를 표시한다.

1. `INTAKE` 접수 점검
2. `ANALYSIS` 사진 분석
3. `CONCEPT` 컨셉 2안
4. `GUIDE` 제작 가이드
5. `IDENTITY TEST` 외형 테스트
6. `SCENES` 장면 제작
7. `EDIT & QC` 편집·검수
8. `DELIVERY` 고객 확인·납품

각 단계는 `미시작`, `진행 중`, `보완 필요`, `승인 완료` 중 하나로 표시한다. 주문 상태를 수동으로 먼저 바꿔 우회하는 방식이 아니라, 각 단계의 승인 조건을 DB가 확인한 뒤에만 다음 작업 버튼을 활성화한다.

## 0단계 — 주문 접수·자동 점검

고객이 마지막 신청 버튼을 누를 때 DB에서 자동 검사한다. 이 단계에서는 GPT 분석, 컨셉, Runway 프롬프트를 만들지 않는다.

### 자동 검사 항목

- 주문번호가 생성되었는지
- 사진이 모두 동일 주문과 동일 고객 소유인지
- 대표 얼굴 사진과 대표 전신 사진이 있는지
- 선택된 옆모습·꼬리 및 특정 시기 사진 ID가 실제 주문 사진인지
- 추억이 2~6개인지
- 각 추억에 사진이 1~5장 연결됐는지
- 추억에 연결된 사진이 합계 5장 이상인지
- 약관·개인정보·사진 사용 권한·외부 AI 처리 동의가 현재 버전인지
- 사람 포함 여부와 처리 방법이 기록됐는지
- 미성년자 포함 시 보호자 동의가 기록됐는지
- 같은 사진이 다른 고객 주문과 잘못 연결되지 않았는지

### 결과

- 통과: `orders.status = materials_submitted`, `photo_analysis_status = pending_operator_review`
- 실패: 주문 접수 자체를 거절하고 고객에게 수정할 항목을 표시

관리자 화면에서는 자동 점검 결과를 모두 읽기 전용 체크리스트로 보여준다. 하나라도 실패하거나 확인할 수 없으면 1단계 승인 버튼을 비활성화한다.

## 1단계 — 사진·신청 내용 분석

운영자가 주문을 `reviewing_materials`로 연 뒤 고객 JSON과 사진을 GPT에 전달한다. GPT 결과를 그대로 승인하지 않고 관리자 화면에 저장한 뒤 사람이 확인한다.

### 저장할 분석 결과

```json
{
  "observed_facts": [],
  "unknown_or_uncertain": [],
  "photo_roles": [
    {
      "asset_id": "uuid",
      "filename": "photo.jpg",
      "role": "face_reference | body_reference | side_tail_reference | memory_scene | original_still_only | unsuitable",
      "reason": ""
    }
  ],
  "identity_profile": {
    "face_shape": "",
    "eyes": "",
    "nose": "",
    "ears": "",
    "fur_color_and_pattern": "",
    "body_shape": "",
    "tail": "",
    "locked_traits": []
  },
  "production_risks": [],
  "customer_questions": [],
  "people_photo_assessment": "",
  "operator_notes": ""
}
```

`asset_id`는 반드시 해당 주문의 `source_image`여야 한다. 파일명만으로 연결하지 않는다.

### 운영자 판정

- `approved`: 분석 결과와 기준 사진이 충분함. 2단계 가능
- `needs_customer_input`: 추가 사진이나 답변이 필요함
- `pending_operator_review`: GPT 결과 저장 후 아직 사람이 검토하지 않음

`needs_customer_input`일 때는 고객에게 필요한 사진이나 질문을 메시지로 보낸다. 고객이 자료를 추가·변경하면 기존 승인을 자동 취소하고 `pending_operator_review`로 되돌린다.

### 승인 필수 조건

- 사진 역할과 외형 유지 기준표가 저장됨
- 대표 얼굴·전신 사진이 실제 주문 사진임
- 외형상 확인 불가능한 부분이 명시됨
- 사람·미성년자 사진 처리 방식이 고객 동의와 일치함
- 제작 위험 요소 또는 `없음`이 명시됨
- 추가 질문이 남아 있지 않거나 운영자가 답변 불필요로 판정함

## 2단계 — 컨셉 2안

1단계가 `approved`일 때만 관리자 화면의 컨셉 입력 영역을 활성화한다.

### 컨셉 규칙

- A안: 실제 추억 재현형
- B안: 영화적 감정 확장형
- 각각 5~7개 이야기 장면
- 고객에게 보여줄 일본어 제목, 톤, 짧은 소개, 장면 목록
- 고객이 제공하지 않은 사실을 확정적으로 추가하지 않음
- 사람 얼굴을 AI로 생성하는 장면을 넣지 않음
- 이 단계에는 Runway 프롬프트를 저장하지 않음

두 안을 공개하면 `orders.status = concepts_ready`가 된다. 고객이 명시적인 전송 버튼으로 한 안을 선택하면 `concept_selected`가 된다. 제작 시작 전까지는 운영 정책에 따라 선택 변경을 허용할 수 있지만, 제작 가이드가 확정된 뒤에는 운영자 확인 없이 변경하지 않는다.

## 결제 위치

컨셉 선택 후 제작 가이드 확정 전까지 Stripe 결제를 요청한다.

- 컨셉을 보기 전에는 결제를 강요하지 않음
- 결제 전에도 운영자는 선택 컨셉의 제작 가이드 초안을 만들 수 있음
- Runway 크레딧이 발생하는 외형 테스트와 장면 생성은 `payment_status = paid` 이후에만 가능
- 확인 영상 공개와 최종 납품도 입금 확인 전에는 DB에서 차단

## 3단계 — 선택 컨셉 제작 가이드

고객이 선택한 한 가지 컨셉만 대상으로 작성한다. 이 자료는 고객 공개용 컨셉과 분리된 운영 전용 문서다.

### 60초 기본 편집 구성

| 구성 | 권장 시간 | 사용 자료 |
| --- | ---: | --- |
| 원본 사진 슬로 줌·패닝 | 약 25초 | 고객 원본 사진 |
| AI 생성 영상 | 약 20초 | 승인된 기준 사진에서 생성한 4~5초 클립 |
| 장소·빛·계절 연결 | 약 10초 | 강아지 얼굴이 필요 없는 연결 장면 |
| 엔딩 | 약 5초 | 원본 사진과 고객 메시지 |

총 길이는 55~65초 안에서 조정한다. 전체 60초를 AI 영상으로 채우지 않는다.

### 장면별 저장 항목

- 장면 순서와 제목
- 장면 종류: `original_photo`, `ai_video`, `bridge`, `ending`
- 예상 길이
- 기준 사진 `asset_id`
- 강아지 행동 한 가지
- 영어 Runway 프롬프트
- 피해야 할 변형
- 결과 검수 기준
- 자막 또는 엔딩 문구

한 장면에 행동을 여러 개 요구하지 않는다. 프롬프트는 고객에게 공개한 컨셉의 사실 범위를 벗어나지 않아야 한다.

## 4단계 — 외형 유지 테스트

제작 가이드를 확정하고 입금이 확인되면 `orders.status = production`으로 이동한다.

첫 번째 작업은 전체 장면 생성이 아니라 외형 유지 테스트 한 건이다.

### 테스트 조건

- 대표 얼굴 또는 대표 전신 사진 1장
- 가장 단순한 행동 1개
- 4~5초
- 카메라 움직임 최소화
- 사람 얼굴 생성 없음

### 검수 항목

- 얼굴형
- 눈 크기·간격·색
- 코 모양과 위치
- 귀 길이와 방향
- 털 색과 무늬
- 몸 크기와 다리 수
- 꼬리 길이와 모양
- 목줄·리드줄 중복 여부

### 판정

- `approved`: 다음 장면 생성 가능
- `retry`: 수정 프롬프트를 기록하고 재생성
- `rejected`: 고객에게 보여주지 않고 원인 기록

외형 테스트가 `approved`가 아니면 나머지 AI 장면의 생성 완료 처리를 DB에서 막는다.

## 5단계 — 장면별 수동 생성·검수

운영자는 장면을 한 개씩 진행한다. 각 장면에는 생성 횟수와 마지막 판정을 남긴다.

### 장면 상태

```text
planned
  → generating
  → generated
  → usable            그대로 사용 가능
  → edit_fix          편집으로 보정 가능
  → retry             재생성 필요
  → rejected          고객에게 보여주면 안 됨
```

`retry` 후에는 수정한 프롬프트와 재생성 사유를 새 시도로 남긴다. 기존 실패 결과를 덮어쓰지 않는다. Runway 프로젝트 URL, 사용 모델, 길이, 크레딧, 생성 시각도 함께 기록하면 초기 10건의 원가 계산에 사용할 수 있다.

모든 AI 필수 장면이 `usable` 또는 `edit_fix`가 되어야 편집 완료 단계로 갈 수 있다. `generated`나 `retry` 상태가 남아 있으면 고객 확인 영상 업로드를 막는다.

## 6단계 — 편집·내부 검수

원본 사진, 승인된 AI 클립, 연결 장면, BGM, 엔딩을 약 1분으로 편집한다.

### 내부 검수

- 컨셉과 장면 순서가 일치함
- 원본 사진과 AI 장면의 외형이 크게 달라지지 않음
- 리드줄·다리·꼬리·눈 등 생성 오류가 화면에 남지 않음
- 사람 얼굴 처리 방식이 고객 선택과 일치함
- 고객이 제외해 달라고 한 내용이 없음
- BGM 음량이 과하지 않음
- 자막과 이름 표기가 정확함
- 55~65초 내외임

검수가 완료되기 전에는 확인 영상 업로드 버튼을 활성화하지 않는다.

## 7~8단계 — 고객 확인과 납품

내부 검수가 끝난 확인 영상만 고객에게 공개하고 `customer_review`로 이동한다.

- 수정 요청이 들어오면 `revision_requested`
- 수정 영상 공개 전에는 수정 요청을 처리 완료로 바꿀 수 없음
- 열린 수정 요청이 있으면 고객 최종 확정과 납품을 막음
- 고객이 특정 확인 영상을 `이 영상으로 확정`하면 승인 시각과 영상 ID를 저장
- 고객 승인 후 `quality_check`
- 최종 파일을 등록하고 `delivered`

## 관리자 화면 권장 순서

한 주문 상세 안에서 다음 순서로 배치한다.

1. **운영 체크리스트** — 현재 막힌 단계와 다음 행동 한 가지
2. **접수 자동 점검** — 동의, 사진 수, 사진 소유권, 사람·미성년자 처리
3. **사진 분석** — GPT 분석 결과 입력·복사, 운영 승인 또는 고객 보완 요청
4. **고객 이야기와 사진** — 원본 내용 확인
5. **컨셉 A·B** — 분석 승인 후 활성화
6. **선택 컨셉 제작 가이드** — 고객 선택 후 활성화
7. **외형 테스트** — 결제·가이드 확정 후 활성화
8. **장면 제작 보드** — 장면별 프롬프트, 결과, 재생성 횟수, 판정
9. **편집·내부 QC** — 체크리스트 완료 후 확인 영상 업로드 활성화
10. **수정·고객 승인·최종 납품**
11. **고객 연락** — 어느 단계에서도 접근 가능

모바일에서는 위 항목을 아코디언으로 보여주고, 현재 해야 할 단계만 처음부터 펼친다. 하단 고정 영역에는 `다음 작업` 버튼 하나만 보여준다.

## 시스템 차단 규칙

다음 규칙은 UI 안내만이 아니라 DB RPC에서 검증한다.

1. 접수 자동 점검 실패 → 사진 분석 승인 불가
2. 사진 분석 미승인 → 컨셉 공개 불가
3. 컨셉 2안이 각각 5~7장면이 아님 → 고객 공개 불가
4. 고객 컨셉 미선택 → 제작 가이드 확정 불가
5. 입금 미확인 → 외형 테스트·Runway 생성 시작 불가
6. 외형 테스트 미승인 → 나머지 AI 장면 승인 불가
7. 장면에 다른 주문의 사진 ID 사용 → 저장 불가
8. 필수 장면에 `retry`·`rejected`·`generated`가 남음 → 편집 QC 완료 불가
9. 편집 QC 미완료 → 고객 확인 영상 공개 불가
10. 열린 수정 요청 존재 → 고객 최종 확정·납품 불가
11. 고객 최종 승인 기록 없음 → 최종 납품 불가

## 초기 10건에서 기록할 운영 지표

- 주문당 사진 수와 추가 사진 요청 횟수
- 사진 분석·컨셉·가이드 작성 시간
- 외형 테스트 통과까지의 생성 횟수
- 장면별 생성 횟수와 사용 크레딧
- `usable`, `edit_fix`, `retry`, `rejected` 비율
- 최종 편집 시간
- 고객 수정 횟수
- 주문당 총 작업 시간과 총 Runway 비용

이 지표를 기준으로 정가, 납기, 수정 횟수, Runway 플랜과 자동화 범위를 결정한다.
