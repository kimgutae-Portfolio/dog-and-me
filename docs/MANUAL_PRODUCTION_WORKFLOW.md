# WAN MEMORY 움직이는 동화책 제작 운영 흐름

## 운영 원칙

고객에게는 글쓰기나 사진 분류를 과하게 요구하지 않는다. 고객이 하는 일은 물語로 남길 3~5개의 날을 고르고, 각 물語에 같은 날의 사진을 최소 1장 첨부하는 것뿐이다. 정면·전신·옆모습 공통 기준 사진은 받지 않는다.

관리자는 주문 전체의 외형 기준표를 먼저 만드는 대신, 물語 하나를 하나의 제작 단위로 다룬다. 물語마다 첫 번째 사진을 기준 사진으로 고정하고 2~3번째 사진은 부족한 정보만 보충하는 참고 자료로 사용한다. 서로 다른 물語의 장소·계절·의상·소품을 섞지 않는다.

## 전체 순서

```text
0. 고객 접수
   └─ 물語 3~5개 + 각 물語 사진 1~3장
        ↓
1. 물語별 제작 소재 확인
   ├─ 부족함 → 해당 물語만 구체적으로 추가 요청
   └─ 운영 승인
        ↓
2. 전체를 잇는 물語안 A·B 제안
        ↓ 고객이 1안 선택
3. 결제 요청·입금 확인
        ↓ paid
4. 물語별 그림책 페이지 + 한 문장 제작
        ↓ 모든 페이지 고객 확인
5. 승인된 페이지를 Runway로 한 장면씩 움직임
        ↓
6. 자동 자막·BGM·장면 연결 및 내부 QC
        ↓
7. 고객 확인 영상 → 수정 → 최종 승인
        ↓
8. 완성본과 전용 물語 사이트 납품
```

## 0단계 — 고객 접수

### 고객이 입력하는 항목

- 반려견 이름, 견종, 나이, 성격
- 물語 3~5개
- 각 물語의 제목과 30자 이상의 설명
- 각 물語와 같은 장면의 사진 1~3장
- 마지막에 전하고 싶은 말
- 약관, 사진 사용 권한, 외부 AI 처리, 그림책 재구성 확인

시기와 장소는 선택 입력이다. 영상 프롬프트, 화풍, 화면비, 내레이션, BGM은 고객에게 선택시키지 않는다.

### 사진 규칙

- 사진 1: 해당 물語의 필수 기준 사진
- 사진 2~3: 필요한 경우에만 사용하는 보조 사진
- 같은 사진을 여러 물語에 중복 연결하지 않음
- 다른 물語의 사진을 참고해 보이지 않는 특징을 추측하지 않음
- 사람 얼굴은 새로 생성하거나 사용하지 않음

DB는 주문 제출 시 물語 수가 3~5개인지, 각 물語에 위치가 지정된 사진이 1~3장인지 확인한다. 통과하면 `materials_submitted`와 `pending_operator_review`로 전환한다.

## 1단계 — 물語별 제작 소재 확인

관리자 첫 화면에는 공통 외형 사진 대신 물語별 카드가 표시된다.

각 카드에서 확인할 내용:

- 제목과 고객 설명
- 시기와 장소
- 첫 번째 기준 사진
- 0~2장의 보조 사진
- 기준 사진만으로 구도, 계절, 배경, 반려견 모습이 충분히 읽히는지
- 사람 얼굴이나 사용하면 안 되는 요소가 있는지

부족한 경우 “옆모습 사진을 보내주세요”처럼 막연하게 요청하지 않는다. “바다 물語의 기준 사진에서 목줄 색이 보이지 않아, 같은 날 목줄이 보이는 사진 1장을 추가해 주세요”처럼 물語와 부족한 정보만 지정한다.

모든 물語가 제작 가능하면 소재 승인을 누른다. 이 승인 전에는 물語안 공개, 그림책 페이지 공개, Runway 클립 등록이 열리지 않는다.

## 2단계 — 물語안 2개

두 안 모두 고객이 제출한 3~5개의 물語를 빠뜨리지 않는다. 차이는 사건이 아니라 연결 방식에 둔다.

- A안: 하나의 상징이나 물건이 물語들을 여행하는 구조
- B안: 주인공이 발견하고 모으거나 성장하는 구조
- 고객이 제공하지 않은 사실을 확정적으로 추가하지 않음
- 각 물語는 최소 한 장면으로 대응
- 시작과 끝을 포함해 약 5~7개의 그림책 페이지로 확장 가능

고객이 한 안을 선택한 뒤 확정 요금, 납기, 취소 조건과 함께 결제를 요청한다. Runway 크레딧이 발생하는 작업은 `paid` 이후에만 시작한다.

## 3단계 — 관리자 제작 묶음

관리자의 “물語별 제작 데이터 다운로드”는 다음 구조를 만든다.

```text
ORDER-NUMBER/
  order.json
  photo-manifest.json
  GPT_INSTRUCTIONS.txt
  stories/
    01-title/
      original/
        story_01_primary-*.jpg
        story_01_support_1-*.jpg
      runway_16x9/
        story_01_primary-*.jpg
        story_01_support_1-*.jpg
```

GPT나 이미지 제작 도구에는 한 번에 한 물語 폴더만 전달한다. 파일명에 `primary`가 들어간 사진이 구도와 정체성의 기준이다. `support` 사진은 기준 사진과 충돌하지 않는 세부만 보충한다.

## 4단계 — 그림책 페이지와 문장

선택된 전체 물語안에 맞춰 물語별 그림책 페이지를 먼저 만든다. 실사 장면 재현이 아니라 고객 사진의 사건과 감정을 수채·과슈 질감의 한 페이지로 번역한다.

장면마다 저장할 항목:

- 장면 순서
- 장면 제목
- 연결되는 고객 물語
- 기준 사진 ID
- 그림책 페이지 이미지
- 화면에 들어갈 일본어 물語 문장 1개(1~120자)
- Runway에서 허용할 작은 움직임
- 변하면 안 되는 구도와 요소

그림과 문장은 함께 고객에게 공개한다. 고객이 전부 승인하기 전에는 영상화하지 않는다.

## 5단계 — Runway 제작

Runway에는 승인된 그림책 페이지를 입력 이미지로 사용한다. 고객 원본 사진을 바로 크게 움직이지 않는다.

한 클립의 원칙:

- 그림책 페이지 1장당 클립 1개
- 행동은 1개만 지정
- 카메라는 고정 또는 아주 느린 이동
- 눈, 입, 다리, 꼬리의 큰 형태 변화 금지
- 새 물체, 새 동물, 새 사람 추가 금지
- 꽃잎, 빛, 물결, 커튼, 털끝처럼 작은 움직임 우선

생성 결과가 괴상하거나 정체성이 흔들리면 프롬프트를 길게 덧붙이지 않는다. 움직임 범위를 더 줄이거나, 그림책 페이지 자체를 고친 뒤 다시 생성한다.

## 6단계 — 편집과 자동 자막

승인된 장면 순서대로 클립을 배치한다. 관리자에 저장된 장면별 물語 문장을 자동 자막으로 합성하고, BGM과 페이드를 적용한다.

검수 항목:

- 자막이 그림의 중요한 부분을 가리지 않는지
- 자막 순서가 장면 순서와 같은지
- 물語 사이의 색과 질감이 한 권처럼 이어지는지
- 갑작스러운 움직임이나 형태 붕괴가 없는지
- 사람 얼굴이 생성되거나 드러나지 않는지
- 약 1분 안에서 시작·중간·끝이 느껴지는지

## 7~8단계 — 고객 확인과 납품

확인 영상에서 수정 요청을 받고, 계약된 횟수 안에서 반영한다. 최종 승인 후 완성 영상과 전용 물語 사이트를 공개한다. 제작 시간, Runway 생성 횟수, 재시도 횟수와 사용 크레딧은 관리자만 볼 수 있는 운영 기록으로 남긴다.
