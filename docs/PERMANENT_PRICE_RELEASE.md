# 恒常価格 ¥12,800 の反映

`202610150001_permanent_memory_film_price.sql` は、通常価格を税込 ¥12,800 に統一し、20件経過後の値上げ判定を廃止する。

- 新しい注文の作成時・素材の提出時とも `quoted_price` / `regular_price` は 12800、`campaign_id` は null。
- `get_memory_film_pricing()` の既存の返却項目は維持し、価格は両方12800、旧キャンペーンの数値は0、有効フラグはfalseを返す。過去の件数は参照しない。
- 未払い (`pending` / `invoice_sent`) の通常・旧モニター注文で、未完了・未キャンセルかつ見積が12800以上のものを12800へ更新し、注文イベントに更新前の価格とキャンペーンを記録する。
- 入金済み・返金済み・無料提供・納品済み・キャンセル済みの履歴は変更しない。既に個別合意した12800未満の価格やカスタムキャンペーンも引き上げない。
- 現在の認証、写真・物語数、同意バージョン、素材確認ゲートは維持する。過去のマイグレーションは編集しない。

## 承認されたリリース時の手順

1. 一時的に決済開始を止め、進行中の決済リクエストを完了させる。以前の価格を読んだリクエストが反映直後に古い金額でCheckoutを作らないため。
2. 12800超の未払い見積に、作成中・有効・入金済み・返金済みのStripeセッションが残っていないか確認する。
3. 未払いの有効セッションはStripe側で期限切れにし、Webhook等でDBの状態も確定させる。既に決済・返金された場合はそのWebhookを先に処理し、請求履歴は維持する。DBのセッション状態だけを手動で書き換えない。
4. 履歴管理付きの通常のSupabaseマイグレーション手順で適用する。障害条件が残っていれば、明確なエラーで全体をロールバックする。
5. 価格RPCが `(12800,12800,0,0,0,false)` を返すこと、新しいテスト注文の作成・提出が12800になることを確認し、決済を再開する。

リポジトリへの追加やメインへのpushだけでは、リモートDBの関数は更新されない。本番DBへの適用はリリース承認後に別途行う。

## ローカルDB回帰テスト

新規の使い捨てPostgreSQLデータベースに対し、リポジトリルートから実行する。本番・共有DBでは実行しない。

```sh
psql -v ON_ERROR_STOP=1 -f tests/permanent-pricing-db.sql <disposable-database-connection>
```

テストは有効な旧価格セッションを意図的に作り、最初の適用が拒否・ロールバックされることを検証するため、その箇所では想定通りのエラーが表示される。最後の `PASS` 通知と終了コード0で全検証の成功を確認する。
